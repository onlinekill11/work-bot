# 💼 WORK — бот учёта смены и заявок на вывод

Телеграм-бот: `@workebot_bot`
Админ (получатель заявок): `@maximalusdt`

## Что умеет

**Таймер смены**
- «🟢 Начал работу» — старт
- «⏸ Пауза» / «▶️ Пуск» — перерыв, время не идёт
- «⏹ Стоп работа» — смена закрыта, показывает чистые часы
- карточка смены сама обновляется раз в минуту
- смена живёт в базе: перезапуск бота её не теряет

**Как только воркер жмёт «Стоп»** — админу мгновенно летит уведомление:
имя, юзернейм, ID, время смены (16:00 — 05:00), чистые часы и число перерывов.
Это же время автоматически подставляется в отчёт — воркер часы не вводит.

**Заявка на вывод** (7 вопросов, считает бот):
1. Старт — начальный баланс токена
2. Конец — фактический баланс токена
3. Диспуты (в баксах) — вычитаются из конечного баланса
4. Часы смены — подставляются с таймера
5. Блоки и на каких ЛК
6. Сложности за день
7. Планы на завтра

Админу уходит **готовая пронумерованная таблица** с расчётом,
работнику — только его заработок за день.

## Формулы

```
профит   = (конец − диспуты) − старт
ставка   : до 300$ → 12% | 300–500$ → 13% | 500–800$ → 15% | 800$+ → 16%
заработок= профит / 100 × ставка
блоки    → фикс 3.5$ за каждый ЦЕЛЫЙ час смены
итог     = наибольшее из (процент, фикс)      # BLOCK_PAY_MODE=max
```

Если нужно, чтобы при блоках платился **только фикс** (без сравнения с процентом) —
поставь в `.env`: `BLOCK_PAY_MODE=fix`.

Пример: старт 300, конец 900, диспуты 50 → профит 550 → 15% → **82.5$**
(фикс за 13 ч = 45.5$, платится процент, он больше).

## Установка

```bash
pip install -r requirements.txt
```

Создай `.env` рядом с `bot.py` (образец — `.env.example`):

```
BOT_TOKEN=токен_от_BotFather
ADMIN_USERNAME=maximalusdt
ADMIN_ID=
BLOCK_PAY_MODE=max
TZ_OFFSET=3
```

`ADMIN_ID` можно не заполнять: бот сам запомнит админа, когда тот
(с юзернеймом из `ADMIN_USERNAME`) первый раз напишет боту `/start`.
**Важно:** пока админ не нажал `/start`, Telegram не даёт боту ему писать.

## Запуск

```bash
python bot.py
```

или двойным кликом по `start.bat`. Бот работает, пока окно открыто.

# 🌍 Хостинг 24/7 (Render + Neon)

Бот должен работать, когда твой ПК выключен. Схема: код крутится на **Render**,
данные лежат в **Neon Postgres** — при рестартах и передеплоях история заявок,
статистика и активные смены не теряются.

### 1. База в Neon (бесплатно)
1. neon.tech → зарегистрируйся → **Create project** (регион Frankfurt).
2. Скопируй **Connection string** вида
   `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`

Проверить, что база живая, можно прямо с ПК:
```bash
set DATABASE_URL=строка_из_neon      # PowerShell: $env:DATABASE_URL="..."
python selftest.py
```
Прогонит весь сценарий по боевой базе и уберёт за собой тестовые записи.

### 2. Репозиторий
Локальный git уже готов (`.env` и `*.db` в `.gitignore` — токен не утечёт).
Создай **приватный** репозиторий на GitHub и запушь:
```bash
git remote add origin https://github.com/ТВОЙ_ЛОГИН/work-bot.git
git push -u origin main
```

### 3. Render
1. render.com → **New → Blueprint** → выбрать репозиторий (в нём лежит `render.yaml`).
2. Заполнить переменные: `BOT_TOKEN`, `DATABASE_URL` (из Neon).
3. Задеплоить, скопировать адрес сервиса и вписать его в `KEEPALIVE_URL`
   (`https://work-bot-xxxx.onrender.com/health`) → **Save, redeploy**.

Проверка: открой `https://work-bot-xxxx.onrender.com/health` — там
`{"ok": true, "bot": "work", "on_shift": 0}`.

### Что важно знать про бесплатный Render
- **750 часов/мес на аккаунт.** Один сервис 24/7 = ~730 ч. Значит на этом
  аккаунте не должно быть других бесплатных сервисов, иначе всё встанет
  в середине месяца (уже проходили).
- **Сервис засыпает без входящего трафика.** Спасает `KEEPALIVE_URL`
  (самопинг раз в 10 минут). Надёжнее добавить внешний пинг на `/health`
  каждые 10 мин через cron-job.org или UptimeRobot — он поднимет сервис,
  даже если тот всё-таки уснул.
- **Только одна копия бота одновременно.** Если бот крутится на Render,
  локальный `start.bat` должен быть закрыт, иначе Telegram выдаёт Conflict
  и обновления начинают теряться. В логах будет прямое предупреждение.

### Бэкап базы
Neon сам держит историю изменений (Point-in-time restore). Выгрузить дамп руками:
```bash
pg_dump "строка_из_neon" > backup.sql
```
